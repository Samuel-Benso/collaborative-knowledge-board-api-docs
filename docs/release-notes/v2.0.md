# Release notes: v2.0

Version 2 of the Collaborative Knowledge Board API adds real time collaboration: real time events, threaded comments, card moving and version checks that prevent two users from overwriting each other. It also makes two breaking changes to existing endpoints.

| | |
|---|---|
| **Base URL** | `https://api.example.com/v2` |
| **Release date** | To be confirmed ([Q67](../meta/open-questions.md)) |
| **Authentication** | Unchanged from v1. Log in to get a JWT and send it as `Authorization: Bearer <token>`. |

**Upgrading from v1?** Follow the [migration guide](migrate-v1-to-v2.md). It has before and after code for both breaking changes and a test checklist.

## Changes ranked by impact

Changes are ranked by how likely they are to break an existing integration. Fix the breaking changes first.

| Rank | Change | Type | Who is affected | What you must do |
|---|---|---|---|---|
| 1 | Updating or moving a card now requires `version` | **Breaking** | Every client that updates or moves cards | Read `version` from the card, send it in every update or move request, and handle `409 VERSION_CONFLICT`. |
| 2 | List endpoints return paginated objects instead of plain arrays | **Breaking** | Every client that calls `GET /boards` or `GET /boards/{boardId}/cards` | Read the list from `data`, not from the response body, and loop over pages with `page` and `pageSize`. |
| 3 | Cards now include `position` and `version` | Non breaking | Clients that validate card objects strictly | Allow the two new fields. No other action is needed. |
| 4 | New: comments and real time events | Non breaking | No one, unless you want to use them | No action needed. Adopt them when you are ready. |

## 1. Updating or moving a card now requires `version` (Breaking)

Every card now has a `version` number. To update or move a card, send the version you last read. If someone else changed the card in the meantime, the API rejects your request with `409 VERSION_CONFLICT` instead of overwriting their change.

**What you must do:**

1. Store `version` when you read a card.
2. Send it in the body of every update or move request.
3. Handle `409 VERSION_CONFLICT`: reload the card, then retry or ask the user.

A request that omits `version` is expected to fail with `400`. This behaviour is not yet confirmed ([Q65](../meta/open-questions.md)), so always send `version`.

```http
PATCH /cards/c_101/move
Authorization: Bearer <token>
Content-Type: application/json

{ "columnId": "col_3", "position": 0, "version": 4 }
```

A successful response returns the updated card with `version` increased by 1.

Learn more:

- [Move a card (reference)](../reference/cards.md#move-a-card)
- [Conflicts and versions (concept)](../concepts/conflicts-and-versions.md)
- [Migration guide](migrate-v1-to-v2.md)

## 2. List endpoints return paginated objects (Breaking)

`GET /boards` and `GET /boards/{boardId}/cards` no longer return a plain array. They return an object with the items in `data`.

**What you must do:**

1. Read the items from `data`.
2. Use `total`, `page` and `pageSize` to decide whether to request more pages.
3. Do not assume all items fit on one page. The default `pageSize` is 20 and the maximum is 100.

```json
{
  "data": [ { "id": "c_101", "title": "Write launch plan" } ],
  "page": 1,
  "pageSize": 20,
  "total": 134
}
```

Learn more:

- [Pagination (reference)](../reference/pagination.md)
- [Migration guide](migrate-v1-to-v2.md#2-list-endpoints-return-paginated-objects)

## 3. Cards now include `position` and `version` (Non breaking)

| Field | Type | Description |
|---|---|---|
| `position` | integer | The card's place within its column. Starts at `0`. |
| `version` | integer | Changes when the card changes. Send it back when you update or move the card. |

Existing fields are unchanged. See the [cards reference](../reference/cards.md).

## 4. New: comments and real time events (Non breaking)

### Threaded comments

- Create a comment with `POST /cards/{cardId}/comments`. Add `parentId` to reply to another comment.
- Edit with `PATCH /comments/{commentId}` and delete with `DELETE /comments/{commentId}`.
- Only the author can edit or delete a comment. Other users receive `403`.
- Replies can be nested 2 levels deep.

See the [comments reference](../reference/comments.md) and the [comment threading concept](../concepts/comment-threading.md).

### Real time events

- Connect with Socket.io to `wss://api.example.com` and pass the token in the `auth` option.
- Emit `board.join` with a `boardId` to receive that board's events.
- Three events are sent: `card.created`, `card.moved` and `comment.added`.

See the [real time events reference](../reference/realtime-events.md) and the [quickstart](../getting-started/quickstart-move-card-realtime.md).

### Card moving

Move a card within a column or to another column with `PATCH /cards/{cardId}/move`. See [Move a card](../reference/cards.md#move-a-card).

## Known limitations

- Real time events exist only for the three events listed above. There are no events for card updates, card deletions, comment edits or comment deletions ([Q63](../meta/open-questions.md)).
- Events missed while you are disconnected are not replayed. After you reconnect, join the board again and reload its data over REST ([Q61](../meta/open-questions.md)). See [Reconnect to real time events](../how-to/reconnect-to-realtime.md).
